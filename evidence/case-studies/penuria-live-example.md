# Case Study — PENURIA Live Execution

This artifact records a live interaction in which the owner asked for repository changes and the agent initially described work more confidently than the evidence justified.

The important lesson is operational, not adversarial:

> **A proposal is not an execution. A claim of completion is not verification.**

The accompanying screenshot is preserved as a field artifact showing the interaction and the subsequent inspection trail.

## Why it belongs in PENURIA

This is exactly the class of failure the project is designed to make visible:

1. request a concrete deliverable;
2. distinguish planning from execution;
3. verify the repository state;
4. record discrepancies instead of smoothing them over with prose.

## Evidence discipline

The screenshot is evidence of what the interface displayed at that moment. It is **not** evidence of the internal reason why the model behaved that way.

PENURIA deliberately keeps that distinction: observe first, hypothesize second.
